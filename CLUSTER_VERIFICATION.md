# CPU and GPU verification pipeline

This checklist reproduces the scientific gates while keeping hardware claims
auditable.  The checked-in results were generated by one NumPy process on the
Apple M1 CPU recorded in `results/verification_study/execution_manifest.json`.
They are not JAX or CuPy measurements.

## Laptop / CPU

From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[test]'
python -m pytest -q
python tools/run_verification_study.py --max-scaling-qubits 7
python tools/probe_scaling_limit.py --qubits 8 --timeout 45
```

Accept the run only if every field in
`results/verification_study/verification_status.json` is `true`.  Inspect the
Haar, analytic-noise, exact-LI, method-comparison, and scaling CSV files rather
than relying only on figures.

## GPU cluster

Install the CUDA-compatible JAX or CuPy package approved by the cluster.  Do
not copy a wheel command from another machine because CUDA and driver versions
must match the site.

Example Slurm job template (a proposal, not a configuration used for the
reported results):

```bash
#!/usr/bin/env bash
#SBATCH --job-name=nbqst-verify
#SBATCH --nodes=1
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=8
#SBATCH --gres=gpu:1
#SBATCH --mem=64G
#SBATCH --time=02:00:00

set -euo pipefail
export OMP_NUM_THREADS="${SLURM_CPUS_PER_TASK}"
export OPENBLAS_NUM_THREADS="${SLURM_CPUS_PER_TASK}"

python -m pytest -q
python examples/backend_smoke.py
python tools/run_verification_study.py --max-scaling-qubits 7
```

For timing, synchronize before and after each accelerator region
(`jax.block_until_ready` or `cupy.cuda.Stream.null.synchronize`).  Report
compilation/warm-up separately from steady-state time.  Reuse a fixed saved
state/count bundle across NumPy, JAX, and CuPy so the backend comparison does
not mix numerical and sampling differences.

## Mandatory manifest fields before publishing JAX/CuPy data

Record all of the following next to each result table:

- scheduler, job ID, partition/queue, node count, task count, and wall-time;
- node model, CPU model, sockets, physical cores, hardware threads, allocated
  CPUs, RAM requested, and RAM available;
- GPU model, GPU count, memory per GPU, MIG mode/partition if applicable, and
  `CUDA_VISIBLE_DEVICES`;
- driver, CUDA toolkit/runtime, cuDNN if used, JAX/jaxlib/XLA or CuPy version,
  Python, NumPy, BLAS, operating system, and precision/dtype;
- random seeds, qubits, states, settings, shots, repetitions, warm-ups, timed
  iterations, compilation policy, synchronization points, and transfer policy.

Useful capture commands include `nvidia-smi -q`, `lscpu`, `free -h`,
`scontrol show job "$SLURM_JOB_ID"`, `python -m pip freeze`, and the generated
execution manifest.  Check these commands against local cluster policy.

The report's accelerator section must remain marked “pending owner
verification” until the exact values above are confirmed by the experiment
owner and a fresh job produces the corresponding manifest.
